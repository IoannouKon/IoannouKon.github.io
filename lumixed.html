LUMIXED.
Less arithmetic,
more reuse.

A LUT-based mixed-precision matrix multiplication accelerator built in Chisel and integrated with Rocket through RoCC. It combines FP16 activations with low-bit integer weights, reusing products to reduce repeated arithmetic. The next step is bringing per-group scaling into the accelerator and mapping scaled Qwen workloads.

The idea

What if we reuse products instead of multiplying again?

Instead of multiplying every activation-weight pair independently, LUMIXED generates reusable activation products, stores them in local lookup memories, and selects and accumulates the required values. The current RTL includes an FP16 activation path with FP32 outputs, alongside signed integer activation modes and W8, W4 and W2 weights.

It began as my NTUA diploma thesis and continues as a personal hardware research project. The architecture is called LUMIXED; the repository and source packages retain the name LUMAX.

FPGA footprint / ZCU106

Less logic.
Lower estimated power.

LUMIXED supports W8, W4 and W2 in one hardware design. Its smallest routed configuration uses 46.0% fewer LUTs and 78.4% less estimated dynamic power than the 4×4 Gemmini reference; the reductions reach 73.5% and 93.8% against the 8×8 reference.

04 / Next steps

Bring the scales in.
Then run the models.

The ongoing roadmap: integrate per-group scaling inside LUMIXED, map Qwen workloads across three weight precisions, verify the scaled computation, and run it on ZCU106.

01 / Accelerator integration

Per-group scaling in LUMIXED

Add scale handling inside the accelerator so each quantization group contributes with its own scale. Integrate scale loading, group boundaries and scaled partial-sum accumulation with the FP16 datapath.

02 / Workload mapping

Qwen: FP16 × W8, W4 & W2

Extend the existing raw-coefficient tests to scaled Qwen linear layers: start with official W8/W4 quantized checkpoints and their group scales, then map community W2 checkpoints with their corresponding scales and quantization metadata.

03 / Numerical verification

Check the scaled kernels in Verilator

Compare FP16 × W8, FP16 × W4 and FP16 × W2 results against independent references that include the checkpoint scales. Check weight packing, group boundaries and numerical behavior before progressing to model execution.

04 / On-board execution

Run the workloads on ZCU106

Integrate the verified scaled datapath into the Rocket/Chipyard FPGA system, build the updated bitstream, and run the mapped Qwen workloads on the physical board. Measure correctness, latency and resource use for the tested configurations.
