Project 01 / NTUA diploma thesis · Sep 2024–Sep 2025

LUMIXED.
Less arithmetic,
more reuse.

I developed a configurable Chisel RTL generator for a LUT-based, multiplier-free GEMM accelerator and integrated it into a RocketChip RISC-V SoC through RoCC and TileLink DMA. LUMIXED supports FP16 activations with FP32 outputs, plus signed integer activation modes, and runtime-selectable INT2, INT4 and INT8 weights. Its lookup-based datapath reuses activation products instead of using multiplier DSPs in the unscaled design.

The idea

What if we reuse products instead of multiplying again?

Instead of multiplying every activation-weight pair independently, LUMIXED generates reusable activation products, stores them in local lookup memories, then selects and accumulates the required values. The floating-point mode accepts FP16 activations and produces FP32 outputs; configurable integer modes are also available. Weight precision can be selected at runtime from signed INT2, INT4 or INT8.

The RTL also includes optional group-wise scaling with FP16 scales for finite FP16 activations and runtime-selectable signed W8, W4, or W2 weights, and optional zero-weight skipping for eligible FP16 or INT16 windows. These are independent hardware options with configuration constraints; the current cycles and FPGA comparisons remain the existing unscaled results.

It began as my NTUA diploma thesis and continues as a personal hardware research project. The current RTL lives in the LUMIXED generator folder on my Chipyard fork.

LUMIXED RTL generator

LUMIXED generates accelerator RTL from a Chisel configuration. Explore three designs: dense mixed precision, zero weight skipping, and group scaling.

Mixed precision Zero skipping Group scaling

Dense mixed precision

The RTL builds a product table from each FP16 activation tile and reuses it across output columns. Packed signed INT2, INT4, or INT8 weights drive lookup, sign handling, and odd coefficient correction. The banks combine their partial sums and produce FP32 outputs.

The generator sets the number of banks, parallel rows, product table capacity, and DMA buffering. At runtime, software sets the matrix dimensions and weight format. TileLink DMA prefetches weights so loading can overlap computation. The unscaled implementation shown in the FPGA comparison uses 0 DSPs.

Skip zero weights

In eligible FP16 and INT16 windows, each bank skips weight positions whose value is zero. Nonzero weights still select products using their original positions, so they stay paired with the correct activations.

Enable SKIP_ZERO_WEIGHTS in the generator to add this logic. Each bank advances independently through its nonzero positions. The cycle benefit depends on how zeros are distributed across banks. Ineligible windows use dense selection.

Scale partial sums by group

TileLink DMA loads the FP16 scales into local SRAM before compute. Each group along the inner GEMM dimension has a scale per output column. The RTL applies the scale to that group’s contribution, combines the scaled partial sums, and rounds once to FP32.

The generator offers two schedules. Aligned ends compute windows at group boundaries and reduces bank partials before scaling. Deferred keeps the physical windows and tracks partial sums by bank and group.

The same group scaling hardware supports signed W8, W4, and W2 weights at runtime. Before each matmul, software selects a group size of 32, 64, or 128 along the inner dimension. The hardware keeps that size fixed for the duration of the matmul. Software can select a different size for the next call without rebuilding the hardware.

03 / Current progress

From reusable products
to real workloads.

The project includes the FP16-to-FP32 datapath, optional RTL group-wise scaling and zero skipping, low-bit Qwen kernel checks, and routed FPGA implementation reports. The next step is mapping checkpoint scales into Qwen workloads and running them on the board.

Implemented in RTL

FP16 activations, FP32 outputs

The configured floating-point datapath uses FP16 inputs and produces FP32 results. Signed integer activation modes are also supported, with runtime-selectable INT2, INT4 or INT8 weights. The unscaled lookup-based datapath uses no multiplier DSPs.

04 / Next steps

Bring the scales in.
Then run the models.

With group-wise scaling now implemented as an optional RTL feature, the next stage is to map quantized Qwen checkpoints, verify scaled layers, and run them on ZCU106.

01 / Workload mapping

Map scaled Qwen layers

Connect checkpoint group scales and quantization metadata to Qwen linear layers, covering the group scaling path for FP16 activations and signed W8, W4, and W2 weights.

02 / Workload coverage

Qwen: FP16 × W8, W4 & W2

Extend the existing raw-coefficient tests to Qwen linear layers with checkpoint scales: map official W8/W4 checkpoints and community W2 checkpoints with their quantization metadata.

03 / Numerical verification

Check the scaled kernels in Verilator

Compare FP16 × W8, FP16 × W4 and FP16 × W2 results against independent references that include the checkpoint scales. Check weight packing, group boundaries and numerical behavior before progressing to model execution.

04 / On-board execution

Run the workloads on ZCU106

Integrate the verified scaled datapath into the Rocket/Chipyard FPGA system, build the updated bitstream, and run the mapped Qwen workloads on the physical board. Measure correctness, latency and resource use for the tested configurations.
